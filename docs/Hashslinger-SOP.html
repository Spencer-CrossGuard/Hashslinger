Hashslinger SOP

How the tool works and how to run it: functions, settings, upgrade, reinstall, uninstall and delete.

1What it does#

Reads account NT hashes from AD (read-only), looks each one up in a local store of breached and weak password hashes, and writes a CSV of the flagged accounts. Account hashes stay in memory and are wiped after the run. The only network traffic is to the domain controller. Nothing in the tool changes AD.

2Folders#

One folder you pick at setup. Everything lives inside it:

Hashslinger\
  app\            program and scripts (Hashslinger.exe, powershell\, config\ defaults, docs\)
  app-backups\    the last 3 copies of app\ taken before an upgrade or reinstall
  config\         hashslinger.json (the ONE settings file), pattern_rules.json, hashslinger.json.bak-*
  data\store\     master.ntlm (merged hash store) + master.ntlm.manifest.json (which files are merged)
  data\staging\   HIBP\  rockyou\  custom\   (wordlist files)
  reports\        report_<date>.csv
  logs\           audit.jsonl, setup-*.log, SETUP-SUMMARY.txt
  status\         status.json (live progress)
  requests\       analyst request drop box (only if an analyst group is used)
  Hashslinger-Admin.cmd   Hashslinger-Uninstall.cmd
Outside the folderTwo scheduled tasks (Hashslinger-Scheduled, Hashslinger-OnDemand), the DSInternals module (%ProgramFiles%\WindowsPowerShell\Modules), the RSAT AD tools feature, support bundles you create (Desktop), and the service account in AD.

3Service account (created by hand)#

The tool never creates or changes anything in AD. A Domain Admin creates the account once, before install:

# KDS root key, once per forest (skip if Get-KdsRootKey returns one)
Add-KdsRootKey -EffectiveImmediately          # usable after ~10 hours, once every DC has it

# The account. Only the scan server may retrieve its password.
New-ADServiceAccount -Name svc-hashslinger `
  -DNSHostName svc-hashslinger.corp.contoso.com `
  -PrincipalsAllowedToRetrieveManagedPassword (Get-ADComputer SCANSERVER) `
  -KerberosEncryptionType AES256

# Two rights on the DOMAIN ROOT only, "this object only" (never forest, never schema):
#   Replicating Directory Changes       1131f6aa-9c07-11d1-f79f-00c04fc2dcd2
#   Replicating Directory Changes All   1131f6ad-9c07-11d1-f79f-00c04fc2dcd2
# Helper (stays in the package folder, never installed on the scan server): extras\Grant-HashslingerReplicationRights.ps1 -GmsaName svc-hashslinger   (use -WhatIf first)

# On the scan server, elevated
Install-ADServiceAccount svc-hashslinger
Test-ADServiceAccount svc-hashslinger         # must print True
Nothing elseNo other rights and no privileged group membership. The account also needs "Log on as a batch job" on the scan server if the scheduled task will not start.

4Install#

  1. Create the service account (section 3).
  2. Copy the package to the scan server and double-click Setup-Hashslinger.cmd (local administrator).
  3. Pick the install folder, the DC and the service account name. Tick the scope in the tree: ticking an OU includes everything below it, and search keeps parents visible. Optional: rockyou and HIBP files, an offline DSInternals folder.
  4. Choose how scans run (step 4 in the wizard): a scheduled scan (how often, day, start time), on-demand scans for analysts (optional analyst group), or both.
  5. Click Check readiness (changes nothing), then Install. Install is the local install followed by the service account checks.
  6. Setup does not start a scan. Run the first one like every manual scan: Admin tool, Run and logs, Start a scan now. It asks for your EDIPI and a reason or CTO number, then runs the scan as the service account. Watch it with Watch progress.

Hardening the scan server

  • Crash dumps: a crash dump of Hashslinger.exe or powershell.exe can contain account hashes, and Windows Error Reporting may send dumps off the server. Turn it off on this server: reg add "HKLM\SOFTWARE\Microsoft\Windows\Windows Error Reporting" /v Disabled /t REG_DWORD /d 1 /f, and make sure no LocalDumps key exists under it.
  • PowerShell logging: if module logging (event 4103) or transcription is on by policy, look at a sample log after the first scan and confirm no hash values appear. The engine writes accounts to a pipe, not the PowerShell output stream, but check on your build.
  • Local drives only: the tool refuses paths on network shares (store, wordlists, reports, logs, status, requests, allowed report locations).
  • Program folders: after install only Administrators and SYSTEM can change app\, config\ and the install folder itself, and the exe starts PowerShell by its full System32 path. Check with icacls <install folder>\app: no entry for Users or Everyone with write access.
  • Domain Admin scripts (extras\, diagnostics\) are not installed on the scan server. They stay in the package folder.

5A scan, step by step#

StepWhat happens
1 PreflightThe output folder must be under an allowed report location; optional BitLocker check.
2 Merge wordlistsNew or changed files in data\staging are merged into the store (section 8).
3 PatternsBuilds hashed candidates from pattern_rules.json: keyboard walks, base words, leetspeak, seasons, years, suffixes.
4 Pull from ADThe engine (Get-AccountHashes.ps1) runs an LDAP search for the scope (base DN, account types, UAC flags) to get the in-scope account GUIDs, then replicates them with DSInternals.
bulk: one pass over the whole directory, keeping only in-scope accounts. per-account: one call per account. At or below per_account_threshold (5000) bulk switches to per-account on its own, since bulk costs the same for 2 accounts as for all. Explicit -Properties sets are used so Schema partition rights are not needed. Offline mode reads an ntds.dit copy instead. Hashes go to the exe over a pipe, never to disk.
5 MatchHashes are sorted, then looked up in the memory-mapped store (binary search plus a 2-byte prefix index). Pattern candidates, empty password, reversible encryption, LM hash and (if on) duplicates are checked.
6 ReportWrites report_<date>.csv, flagged accounts only. Refuses to write any cell containing an account's hash.
7 WipeZeroes the in-memory hash and name buffers, deletes temp merge folders, writes the audit entry with wipe_confirmed, applies report retention.
  • Watching a scan: the progress window shows the step, how long this step has run, how long since the last message from the engine, and a scrolling log. Step 4 reports sub-steps A (scope search), B (property test), C (replication) with counts, rate per second, elapsed time and a rough time left, every 5 seconds. The same log is in status\status.json (log).
  • One scan at a time (data\store\run.lock, next to the store, so only the service account and administrators can touch it). A second start is refused and logged; an on-demand request that arrives meanwhile is kept, the on-demand task waits (checks every 30 seconds, up to about 24 hours) and runs it as soon as the lock is free. Merges (merge, Admin tool Merge now) use the same lock.
  • The scheduled task runs Hashslinger.exe --config ... scan as the service account on the cadence, day and time in the settings.
  • Memory is about 150 to 250 bytes per account plus 40 for sorting.

8Wordlists and the store#

Drop files in data\staging\HIBP, rockyou or custom. Copy, do not move, so they inherit the folder permissions. The store is a sorted file of 17-byte records: the 16-byte NT hash plus a 1-byte source tag (HIBP, rockyou, custom). Merging is a linear pass with an atomic swap, so a scan never sees a half-written store.

FileHandled as
plain text (default for rockyou, custom)One password per line; the NT hash is computed.
.ntlm (default for HIBP)Lines of HASH or HASH:count.
.tsv and .csvHash column plus password column. The delimiter (tab, colon, comma), which column holds the hash, and an optional header are detected. The first rows are tested: if NT(password) equals the hash column it is used directly; otherwise the NT hash is computed from the password column and the hash column is ignored. Passwords are never stored. Single-column files are NT hash lists.
  • master.ntlm.manifest.json records each merged file by size and modified time. Only new or changed files are merged, all new files of one folder in a single pass, parsed in parallel.
  • Adding a file only adds hashes. Editing or deleting a file you already merged rebuilds that list's share of the store on the next scan or merge: its old hashes are removed from the store and the remaining files of that list are merged again, so a corrected or removed entry stops matching. Other lists (for example HIBP) are not re-read.
  • A file that produces no usable hashes (wrong format, no 32-character hex hash column, empty) is not recorded as merged. The merge log shows a WARNING, and it is tried again next run. Lines in an NT hash file that are not valid hashes are counted and reported.
  • Merge time is mostly disk speed; a full HIBP merge needs about twice the store size free. The source files are plaintext password lists; keep or delete them as you see fit.

11Upgrade#

Whole package

  1. Wait for any running scan to finish, or stop it. Setup refuses to run during a scan.
  2. Unzip the new package somewhere else, not inside the install folder. If it has no Hashslinger.exe, run build.cmd in it, or setup builds one with the in-box compiler.
  3. Run its Setup-Hashslinger.cmd, pick the same install folder (settings load automatically), and click Install.

What it does

Backs up the current app\ to app-backups\app-<stamp> (last 3 kept), copies the new exe, scripts, docs and extras, and re-runs verification and Finish (tasks are re-registered).

What it keeps

Settings, store, wordlists, reports, logs and pattern_rules.json. New settings keys appear in the Admin tool with defaults; click Save to write them.

Single file

With no scan running, copy the new file over the old one in app\ (the exe, or a script in app\powershell), then Unblock-File it. Nothing needs restarting. Settings can be changed in the Admin tool; pattern_rules.json can be edited in place.

Roll back

Copy the contents of app-backups\app-<stamp> back over app\. For settings, copy a config\hashslinger.json.bak-<stamp> over hashslinger.json.

12Reinstall or move#

Reinstall in place

Same as the upgrade. Settings and data are kept.

Clean reinstall

Uninstall with -RemoveAll (section 13), then run setup again. The store is rebuilt from the wordlists you supply.

Move to another drive or folder

Uninstall with no switches (tasks only), copy the whole install folder to the new location, run setup from the package and pick the new folder, then open the Admin tool and fix any path still pointing at the old location (the Where tab). Copying data\store including the manifest avoids re-merging.

New server

Create the service account for the new server name (or add the computer to the existing account's allowed list), then run setup there.

14Delete things#

ToDo
Delete reportsDelete the CSV files in the reports folder, or lower retention_days (applied after each scan).
Clear the audit logDelete logs\audit.jsonl. The next run starts a new one; run ids restart at 001 for the day.
Remove a scopeAdmin tool, Active Directory tab: untick it (or double-click it in the list), then Save.
Drop a wordlistDelete the file from data\staging. On the next scan or merge that list's share of the store is rebuilt from the files that remain, so the deleted file's hashes stop matching.

15Troubleshooting#

SymptomCause and fix
Replication access was deniedOne of the two rights is missing, denied, or not on the domain root itself. The tool already passes explicit property sets so Schema rights are not needed. Run the service account checks; the effective-rights line and the live test say which.
"Only FIPS certified cryptographic algorithms ... MD5"FIPS-only .NET. DSInternals needs MD5 and RC4 for replication, so the scan is blocked (setup and permissions are fine). Needs a policy decision for this server or a different host. Check HKLM:\SYSTEM\CurrentControlSet\Control\Lsa\FipsAlgorithmPolicy, Enabled = 1.
0x80070534, "identity references could not be translated"The server cannot resolve the account through a DC: TCP 445 and 135, Test-ComputerSecureChannel.
Access denied on a wordlistThe file kept its old permissions. Copy it in (do not move it), or run icacls <folder> /T /reset. Finish also repairs this.
Step 4 quiet for a long timeScope search, then a bulk pull of the whole directory; progress lines show counts. Small scopes switch to per-account on their own.
Task will not startGrant the service account "Log on as a batch job".
Scripts blocked or ask to confirmStart from Setup-Hashslinger.cmd (it unblocks), or Get-ChildItem <folder> -Recurse | Unblock-File.
Search base not foundThe Users container is CN=Users, not an OU. Pick it from the tree.
Setup says a scan is runningWait, or Stop-Process -Name Hashslinger.
Need to send diagnosticsAdmin tool, Run and logs, Create support bundle (settings, logs and versions; no reports or hashes).
Hashslinger SOP. Press / to search, Esc to clear.
