Hashslinger: Standard Operating Procedure

1. Purpose and rules

Hashslinger reads password hashes for the accounts you choose, compares them with known breached and weak password lists, and writes a CSV of the accounts that need a password reset. It never stores or shows plaintext passwords, and it never writes hashes to the report.

Authorized use onlyRun it only on a network where you hold documented, signed authorization for this engagement. A scan uses directory replication rights, so it looks like a DCSync to monitoring tools. Tell the SOC before the first scan.
  • Read-only to AD. Nothing in the tool creates, changes or deletes anything in Active Directory.
  • Local only. Account hashes exist in memory during the run and are wiped afterward. The only network traffic is to the domain controller.
  • The report is sensitive. It names accounts with weak or reused passwords. Store and share it only as your tasking allows.

2. Roles

RoleWhat they do
Domain AdminCreates the service account (gMSA) and grants it two replication rights, once, by hand. See section 4.

Report readerReceives the CSV and drives the password resets.

3. Before you start

  • Signed authorization for this network is on file.
  • The scan server is a dedicated member server, not a domain controller, with access limited to the people who need it.
  • Memory: plan for roughly 1.5 GB per 5 million accounts, with a comfortable margin (16 GB or more for large environments).
  • Disk: the full HIBP store is about 17 GB, and a merge needs about twice that free while it runs. Pick a drive that fits.
  • The service account exists and has the two replication rights (section 4).
  • The SOC has been told.
  • The server has the AD PowerShell tools (RSAT). Setup installs them on Windows Server if missing.
  • DSInternals is available: either internet access to the PowerShell Gallery, or a copied module folder for offline servers.
  • FIPS mode is understood. See the FIPS entry in Troubleshooting.

4. Create the service account (Domain Admin, by hand)

Hashslinger does not create the service account and never changes AD. A Domain Admin creates it once. Setup then checks it read-only. Read each command before you run it.

# 1. KDS root key. Once per forest. Skip if Get-KdsRootKey already returns a key.
Add-KdsRootKey -EffectiveImmediately        # usable after about 10 hours, once every DC has it

# 2. The service account. Only the scan server may retrieve its password.
New-ADServiceAccount -Name svc-hashslinger `
  -DNSHostName svc-hashslinger.corp.contoso.com `
  -PrincipalsAllowedToRetrieveManagedPassword (Get-ADComputer SCANSERVER) `
  -KerberosEncryptionType AES256

# 3. Two replication rights on the DOMAIN ROOT only (never the forest, never the schema):
#      Replicating Directory Changes       1131f6aa-9c07-11d1-f79f-00c04fc2dcd2
#      Replicating Directory Changes All   1131f6ad-9c07-11d1-f79f-00c04fc2dcd2
#    Easiest: extras\Grant-HashslingerReplicationRights.ps1 -GmsaName svc-hashslinger   (add -WhatIf first)
#    Or set them in ADSI Edit on the domain root, "this object only".

# 4. On the scan server, elevated:
Install-ADServiceAccount svc-hashslinger
Test-ADServiceAccount svc-hashslinger       # must print True
Least privilegeDo not add the account to Domain Admins or any other privileged group. It needs only the two replication rights. Setup warns if it finds the account inside a privileged group, or if more than one computer may retrieve its password.

The folder extras in the install folder has optional helper scripts for the Domain Admin. Using them is a convenience, never a requirement.

5. Install

Copy the whole Hashslinger folder to the scan server and double-click Setup-Hashslinger.cmd. A local administrator is enough.

  1. Where to install. Click Browse and pick a drive and folder. Everything is created inside a folder named Hashslinger, so the program, settings, data, reports and logs are all in one place. The window shows the exact folder and its free space.
  2. Domain controller. Pick the DC to read from.
  3. Service account name. The gMSA from section 4.
  4. What to scan. A tree like Active Directory. Expand it and tick OUs. Everything underneath a ticked OU is included. Type in the search box to find an OU; its parents stay visible. The list under the tree shows what will really be scanned. Double-click an entry to remove it.
  5. Password lists (optional). Choose rockyou and HIBP files now, or add them later in the Admin tool.
  6. Click Check readiness. It changes nothing and tells you in plain language what would fail.
  7. Click Install. It installs on this server, then runs the service account checks.

When everything is green, click Run first scan. If a check fails, fix it and click Re-run service account checks.

7. Wordlists

Wordlists are the breached and weak passwords a scan matches against. Add them in the Admin tool (Wordlists tab) or copy files into the matching folder under data\staging. Always copy them in rather than moving them, so they take the folder's permissions and the service account can read them.

FolderTypical contentFormat
HIBPHave I Been Pwned NTLM listLines of HASH or HASH:count
rockyouPlain password listOne password per line
customYour own terms or large tablesPlain list, NT hash list, or .tsv/.csv with a hash column and a password column

Hash and password tables (TSV or CSV)

  • The layout is detected: tab, colon or comma separated; hash in the first or last column; optional header row.
  • The first rows are tested. If the NT hash of the password equals the hash column, the hash column is NT and is used directly. If not, the hash column is another algorithm and would never match AD, so the NT hash is computed from the password column and the hash column is ignored. The log says which happened.
  • Passwords are never stored. Only the 16-byte NT hash is kept, plus a small source tag. Duplicates across files collapse. The merged store is far smaller than the source files.
  • All new files for a folder are merged in one pass, parsed in parallel. Large files take a while; the scan prints progress per file.
Originals are plaintext password listsKeep the source files somewhere protected, or delete them after they are merged. The staging folder is locked to the service account and local Administrators.

8. Run a scan

Scans run on the schedule you set (weekly by default) under the service account. To run one now: Admin tool, Run and logs, Start a scan now. A progress window opens.

StepWhat it is doing
1 PreflightChecks the output location and settings.
2 Merge wordlistsMerges any new or changed files from the staging folders.
3 Build patternsPrepares keyboard-walk and base-word candidates.
4 Pull accounts from ADThe longest step. First a scope search, then the replication pull. Progress lines show counts.
5 Match against the storeLooks up each hash. Fast.
6 Write the reportWrites the CSV (flagged accounts only).
7 Wipe and logWipes memory, writes the audit entry.
  • Only one scan runs at a time. A second start is refused and logged.
  • Anyone with read access to the status folder can open the progress window; it does not depend on who started the scan.
  • Small scopes are fast. At or below the small-scope switch (5,000 accounts by default), only the accounts in scope are replicated. Larger scopes use one bulk pass over the whole directory, so the time depends on the size of the directory.
  • The audit log records the time spent in each stage. The Admin tool shows it under Last scan.

9. Read the report

Each scan writes report_<date>.csv in the reports folder. One row per flagged account. Accounts with no finding do not appear. The file never contains hashes or passwords.

ColumnMeaning
sAMAccountNameThe account's sAMAccountName, as AD reports it. Never blank.
OU / Distinguished NameThe account's parent OU or container, to route the reset to the right team.
Account TypeUser, Service or Computer.
Flag ReasonOne or more reasons, separated by semicolons.
SeverityThe highest severity among the reasons.
Scan Run ID / DateTies the row to the audit log entry.

Flag reasons

ReasonSeverity
Found in HIBP breach corpusHigh
Found in rockyou listHigh
Found in custom/organization term listHigh
No password setHigh
Reversible encryption enabledHigh
Matched common-pattern rule (keyboard walk / dictionary base word)Medium
Duplicate password shared with another account (only if duplicate checking is on)Medium

Action: force a password reset for every High row now, and for Medium rows on the normal schedule. Names that begin with a spreadsheet formula character are prefixed with an apostrophe so a spreadsheet will not run them.

11. Troubleshooting

You seeCause and fix
Replication access was deniedThe service account lacks one of the two rights on the domain root, or a Deny overrides it, or the DSInternals version is asking for the Schema partition. The tool passes explicit property sets to avoid the Schema request. Re-run the service account checks: the effective-rights line and the live test show which. Confirm both rights are Allow entries on the domain root, applied to this object.
Only FIPS certified cryptographic algorithms are enabled in .NET ... MD5The server enforces FIPS-only cryptography. Reading password hashes over replication needs MD5 and RC4, so DSInternals refuses to run. Setup, permissions and tasks are unaffected; only the scan is blocked. Options, each needing your security approval: a policy exception for this server only, or an approved host that is not FIPS-enforced. Check: Get-ItemProperty HKLM:\SYSTEM\CurrentControlSet\Control\Lsa\FipsAlgorithmPolicy -Name Enabled (1 means on).
Some or all identity references could not be translated or 0x80070534This server cannot translate the service account's name or SID through a domain controller. Check TCP 445 and 135 to the DC and Test-ComputerSecureChannel.
Access to the path ... is denied on a wordlistThe file kept the permissions of where it came from. Copy the file into the staging folder (do not move it), or run icacls <folder> /T /reset. The service account checks also repair this.
Step 4 shows no progress for a long timeLarge scopes first run a scope search, then a bulk pull of the whole directory. That is expected on large directories; progress lines appear as it goes. For a small scope the tool switches to per-account automatically. If nothing changes for many minutes, check the engine process CPU and connections.
The scheduled task will not startThe service account needs the "Log on as a batch job" right on this server (Local Security Policy, or the GPO).
Scripts are blocked or ask for confirmationDownloaded files are marked as untrusted. Start setup from Setup-Hashslinger.cmd, which unblocks the folder, or run Get-ChildItem <folder> -Recurse | Unblock-File.
Search base not foundThe built-in Users container is CN=Users, not an OU. Pick it from the scope tree instead of typing it.
You need helpAdmin tool, Run and logs, Create support bundle. It contains settings and logs only: no reports, no hashes.

12. Security notes

  • Access. Only the service account, local Administrators and SYSTEM can read the store, wordlists, logs and settings. Failed access attempts are audited if the Audit File System policy is on.
  • Local Administrators on the scan server can read process memory during a scan. Keep that group small.
  • Memory wipe. Account hashes live in one buffer that is zeroed after the run; the audit log records whether the wipe was confirmed. Wiping is best effort on SSDs, so volume encryption (BitLocker) is the real control.
  • Audit log. Every run, including failed ones, records who or what started it, when, how many accounts, where the report went, the wipe result and the time per stage.
  • Report handling. Reports are deleted securely after the retention period if you set one. Treat each report like the credential data it describes.
